# 四日市 3D NANDと東広島Fab15 DRAMの3D学習モデル

キオクシア四日市工場のBiCS FLASHと、マイクロン東広島Fab15のDRAMを選んで学ぶ、日本語・英語・中国語アプリです。初回、または工場版の保存設定がない場合はキオクシア四日市版を表示します。ヘッダーからMicron Fab15版も選択できます。両社のデータと公開資料は独立して管理します。

公開資料で確認できる範囲、過去の公開記録、模式表現を工程ごとに区別します。両社が公開した実工程図や工場配置図ではありません。

**工程順、反復回数、装置の外観・内部構造・寸法・台数、フロア配置、搬送経路、処理時間、ウェーハ断面、層数、検査位置は説明用の模式表現です。実際の製造レシピ、装置メーカー・型番、実測値、歩留まりは再現していません。**

切断、組立、封止、パッケージ製品の最終試験は、両モデルの対象外です。この除外は、それぞれの工場に後工程が存在しないという断定ではありません。

## Sites

Sites配信先は [メモリ製造工程3D](https://memory-ic-fabrication-3d.huamengdiqidiguo.chatgpt.site) です。初回公開は所有者のみが閲覧できる私有サイトとして作成します。工場版・言語・昼夜の設定は閲覧ブラウザごとに保存します。

`.openai/hosting.json` にSite IDと静的出力先 `dist` を保存します。同期用チェックアウト `.sites-checkout/` はGitHub管理対象外です。公開にはSitesのソース同期・ビルド・保存・デプロイを行い、GitHubへのpushだけでは更新されません。

## 起動する

Node.js 24とnpmで動作を確認しています。

```sh
npm install
npm run dev
```

開発用は `http://127.0.0.1:5173/`、ビルド済みのプレビューは `http://127.0.0.1:4173/` です。

```sh
npm run build
npm run preview
```

`dist/` が静的配信用のビルドです。HTMLを直接ダブルクリックせず、ローカルサーバーから開いてください。

## 使い方

- ヘッダーで「KIOXIA｜四日市・3D NAND」または「Micron｜東広島 Fab15・DRAM」を選択します。工場版を切り替えると、工程選択、デモの位置・状態・速度、表示範囲、ラベル、視点、搬送説明、開いた解説・資料ダイアログを、その版の初期状態へ戻します。言語と昼夜は保ちます。
- 昼・夜モードと日本語・English・中文を選択すると、工程名、装置ラベル、説明、模式図、公開資料の説明、操作名を切り替えます。
- 言語・昼夜を切り替えても、工程選択、再生位置、再生／停止、速度、ラベル表示、視点、開いた工程解説を保ちます。言語・昼夜・選択した工場版はブラウザに保存し、再読込後も使用します。
- 夜モードでは画面の配色と3D背景・床・照明を切り替えます。実工場の昼夜操業や照明条件を示すものではありません。
- ドラッグで回転、ホイール・ピンチで拡大縮小、右ドラッグで移動。
- 装置、ラベル、下部の工程区分を選ぶと、公開資料の根拠、未確認事項、学習用解説を表示。
- 黄色の「OHT搬送レール」と「FOUP搬送容器」の名札、または3Dのレール・容器を選ぶと、搬送・昇降とウェーハ保護の役割を3言語で表示。FOUPの名札は搬送中の容器を追い、狭い画面では引出線で位置を示します。
- 搬送設備の説明を開いても工程選択・再生位置・再生状態を保ちます。「工程の説明に戻る」で工程パネルへ戻ります。スマートフォンでは搬送設備を選ぶと説明パネルまでスクロールします。
- 「この工程に移動」で選択した装置を拡大。スマートフォンでは3Dビューまでスクロール。
- 「全体」「前工程」「検査」（Fab15版では「プローブ」）で視点を切り替え。「視点を戻す」で全体へ戻る。
- 再生・一時停止、前後の区間、再生位置、0.5×・1×・2×の速度を操作。
- 描画が中断された場合は進度の時計を止め、WebGLの復旧後に環境光・陰影を作り直します。言語、昼夜、工程選択、視点、再生／停止の意図を保ちます。自動で復旧しない場合は「3D表示を再試行」を選択できます。
- 「工程管理・DXの視点（一般例）」は学習用の一般的なデータ活用例。各工場の実装や改善効果を示すものではありません。
- 「公開資料・確認範囲」で公開日、証書期限、確認内容、確認できない内容を表示。
- 四日市版の資料ダイアログではFab15 DRAM版との違い、Fab15版では以前の汎用DRAMモデルとの違いを3言語で表示。

## 2つのモデルと9つの分類

番号は分類用です。実際の工程順を示しません。両モデルは成膜・リソグラフィ・エッチング・洗浄・CMP等の分野を共有しますが、DRAMと3D NANDではセル構造と工程の組合せが異なります。

| 分類 | キオクシア四日市・BiCS FLASH | Micron東広島Fab15・DRAM |
| --- | --- | --- |
| 1 | ウェーハ搬送・保管 | ウェーハ搬送・保管 |
| 2 | ウェット処理・洗浄 | ウェット処理・洗浄 |
| 3 | 多層膜の堆積 | 薄膜形成・成膜 |
| 4 | フォトリソグラフィ | フォトリソグラフィ |
| 5 | 高アスペクト比エッチング・メモリホール | ドライエッチング |
| 6 | メモリセル・電極形成 | 拡散・イオン注入・熱処理 |
| 7 | CMP・平坦化 | CMP・平坦化 |
| 8 | CBA・ウェーハ貼り合わせ | 計測・欠陥検査 |
| 9 | ウェーハ検査・電気評価 | プローブ検査 |

四日市版は多層膜、垂直メモリホール、セル膜・電極、CBAを模式表示します。CBAは第8世代の公開例です。メモリセルアレイ用とCMOS回路用のウェーハを独立に製造して貼り合わせる考え方を、接合区画で説明します。独立したCMOS側の全工程や二系統の物流全体は描いていません。現在の全製品がCBAを用いるとの表示でもありません。

四日市版の学習用デモは10区間です。

```text
搬送 → Wet → 多層膜 → リソグラフィ → メモリホール加工 → Wet
→ セル・電極形成 → CMP → CBA → 検査・電気評価
```

四日市版の経路は `src/data/kioxiaProcesses.ts` の `KIOXIA_DEMO_ROUTE`、Fab15版の16区間は `src/data/processes.ts` の `DEMO_ROUTE` に定義し、`src/data/modelProfiles.ts` で選択します。実処理順、回数、時間を推定した経路ではありません。OHTの台車は軌道上を移動し、FOUPの昇降部だけが上下します。搬送設備の構成・型式・容量は模式例です。

## 保存する3Dモデル

日本語の標準出力は、[キオクシア四日市_3D-NAND製造工程_公開資料模式モデル.glb](output/キオクシア四日市_3D-NAND製造工程_公開資料模式モデル.glb)と[東広島Fab15_ウェーハ製造工程_公開資料模式モデル.glb](output/東広島Fab15_ウェーハ製造工程_公開資料模式モデル.glb)です。アプリ内の「GLBを保存」でも選択した工場版を出力できます。

GLBには9分類の装置、搬送容器、フロアを含めます。工場版、メモリ種類、工程名、公開資料、確認範囲、未確認事項、搬送設備の役割と模式表現の範囲をメタデータに保存します。資料は四日市版8件、Fab15版13件です。アプリからの出力では選択中の言語を工程グループ名・説明メタデータ・ファイル名へ反映し、内部部品の検索用名は日本語を維持します。

選択枠を除外した静止モデルです。Webのラベル、説明パネル、工程デモのアニメーションは含まれません。`EXT_mesh_gpu_instancing` と `KHR_materials_emissive_strength` を使用します。四日市版の多層膜・孔・CBA形状も説明用であり、層数・実断面・接合精度の仕様を示しません。

画面は描画回数を減らす合成モデルを使い、保存時だけ共有ジオメトリを使う独立モデルを一時生成します。床の昼夜材質と可動部の保存時の姿勢を引き継ぎ、搬送台車は最初の区画に戻して昇降部を格納します。出力の成功・失敗にかかわらず一時モデルを解放し、表示中のモデルには影響を与えません。画面はGLBを読み込まずコードから生成するため、GLBの縮小自体は首画面の読込時間を短縮しません。

## 描画負荷の抑制

- 一時停止中は画面を連続描画しません。再生、カメラ操作・移動、工程選択、停止中の位置調整、表示範囲、昼夜、言語、ラベル、サイズ・フォント変更で描画を再開し、動きが収まると停止します。非表示タブでは描画予約を解除します。
- ラベルのサイズは一括測定して保存し、言語・フォント・表示領域のサイズ変更時に更新します。毎フレームの寸法読み取りを避け、位置と表示状態が変わった要素だけ書き換えます。
- 同じ材質の不透明な静的部品を工程区分・OHT・各FOUPの範囲内で合成します。透明面、既存のインスタンス、可動部、選択枠は個別に維持し、クリックの意味とアニメーションを保ちます。

`http://127.0.0.1:4173/?perf=1` で `.scene-host` の `data-render-frames`、`data-render-calls`、`data-render-triangles`、`data-label-measurements` を読み取れます。通常表示では計測属性を更新しません。描画回数と測定回数はページ読込後の累計、callsとtrianglesは直近の描画値です。`buildFab({ optimizeStatic: false })` で合成前の形状と比較できます。

## ソース構成

- `src/scene/buildFab.ts`：工場版ごとの9分類。四日市の多層膜・縦孔・CBAとFab15のDRAM工程を模式表示。
- `src/scene/FabScene.tsx`：描画、回転、クリック、FOUP搬送、根拠情報付きGLB出力。
- `src/lib/demandLoop.ts`：必要なときだけ動く描画予約と非表示・破棄処理。
- `src/lib/contextRecovery.ts`：WebGL中断・復旧・再試行、破棄済みの復旧結果の無効化。
- `src/scene/exportFab.ts`：共有ジオメトリを使う保存用モデルと一時リソースの解放。
- `src/scene/createEnvironment.ts`：環境光の生成、失敗時の描画状態とリソースの後始末。
